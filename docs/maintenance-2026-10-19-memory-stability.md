# 0.3.2：降低内存占用与增强异常处理（2026-10-19）

基于 0.3.1 的六项 review 修复：

1. 系统 SSH 输出限制真正生效：stdout/stderr 各保留最多 10 MiB，超限仍排空管道、解析结束标志和退出码，output_truncated 如实返回。Windows 事件队列限制为 16×8 KiB，增量解析不再反复扫描全部输出；保留少量启动错误信息用于诊断。
2. Windows SSH 会话锁等待、命令写入确认和结果读取共用截止时间；超时失效并关闭会话，不自动重放。Unix 主连接探测/认证及执行共享预算，自动化路径并行处理三个管道。
3. 传输退出及管道 EOF 都受预算约束，取消时关闭异步管道，不再无期限等待 reader.join。Windows 优先 Job Object 清理后代进程，受限环境回退有界 taskkill；强制收尾额外余量约 1.2 秒。
4. journal 从文件尾部按固定块读取，够数即停止；单行最大 16 MiB，单次 limit 0–1000，不读入全部历史。
5. 审计同样反向读取，正确取得月末最新记录和跨月 offset；不再只收集文件开头的一段再倒序。
6. 数组只打乱索引，资源预检不生成脚本；归档逐项写入独占临时文件并从磁盘上传，取消整份命令克隆和完整 TAR 驻留。commands.tsv 仍按单个受计划预算约束的成员生成。兼容 BatchPlan::build/archive 库 API 保留，生产 CLI/MCP 使用流式路径。

## 验收

Windows GNU：cargo check --workspace --all-targets --locked --offline、Release 构建通过。130 项普通测试通过；额外执行 3 项 MCP 模拟集成、1 项原始 Perl 提交逻辑一致性、1 项真实本地 rsync 二进制/中文路径往返，共 135 项通过。没有安装 rustfmt/clippy，未宣称这些检查通过。

新增回归覆盖：分块和截断标志、退出码、截断后的同一 SSH 会话继续执行、阻塞 stdin、忙会话锁、父进程退出但后代持有管道、两个输出流超限、17 MiB 旧行前缀、1200 条审计及跨月分页、流式归档与旧 API 字节一致（含 cwd 前缀）、磁盘写入失败。

同一份 24.16 MiB、24000 条诊断历史，以独立 Release MCP 进程查询 limit=1，最新索引均为23999：0.3.1 峰值工作集76.78 MiB，0.3.2为13.07 MiB（该场景减少约83%）。此数值不代表所有操作或长期常驻内存。原始测量记录保留在本机私有证据中。
